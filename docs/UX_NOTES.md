# 体验说明（UX Notes）

这份文档记录**界面为什么是这样**：哪些是刻意的取舍、哪些是已知的粗糙、哪些是暂时不做的。
它不是设计规范（见 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)），而是**维护者交接笔记**——避免后来者把「刻意的选择」当成 bug 去修，或把「已知缺口」当成意外。

每条结论都在真实浏览器里走过一遍（空数据库 + 已有数据两种状态），不是凭设计文档推导。

---

## 1. 一条贯穿全局的原则：宁可显示「没有」，也不凭空造数

这个产品的可信度建立在一件事上：**界面上的每个数字与状态都能追溯到后端的一条记录**。由此派生出几条硬约定：

| 约定 | 表现 | 反例（刻意避免） |
| --- | --- | --- |
| 字段缺失显示「—」 | 进度页、结业页 | 补 0、估算、沿用上次的数字 |
| 未确认时区不推导「今天」 | 首页直接说「时区未确认前本页不推导今天」 | 用服务器时区猜一个 |
| 没有数据就说没有 | 错题本空态：「答错一道练习后，第二天起才会出现在这里」 | 塞入示例数据撑场面 |
| 计划完成 ≠ 学会 | 每条完成项都注明「计划完成不等于课程完成或能力等级」 | 用「已掌握」概括一切 |

## 2. 证据分级：通过与否之外，还有「凭什么说通过」

练习有三档证据，标签固定、颜色固定：

| 标签 | 来源 | 含义 |
| --- | --- | --- |
| 已验证（静态规则） | 判题命中全部必须写法、未命中禁止写法 | 文本层面成立；**不代表代码能跑** |
| 未验证（自检） | 学习者勾选「我已在本地运行并通过」 | 只是声明，系统没验证过 |
| 未提交 | 没有提交记录 | — |

只有第一档可能是 `assessed`。**没有任何路径会产出 verified**，也没有任何路径写能力等级。

## 3. 空状态是设计出来的，不是没做完

新人会连续遇到四个空状态，每一个都给了「下一步该做什么」：

1. **首页（未确认时区）**：说明不推导今天，给出去档案页的按钮；
2. **计划页（没做过诊断）**：横幅提示「计划现在只能按默认 L0 排」，并给出「去做诊断」；
3. **错题本（没有错题）**：说明何时会出现第一条；
4. **结业页（未达标）**：四条要求全部显示真实进度（如 0/11、0/6），未达标就说未达标。

## 4. 学习者永远知道「下一步去哪」

这是花了三轮补上的：

- **课程页**：底部有「上一课 / 下一课」（按 `stage, order_index` 计算；第一课只有下一课、最后一课只有上一课）；
- **练习页**：提交后按结果给方向——通过且同课还有题 → 「继续下一题：<标题>」；已是最后一题 → 提示回周计划；未通过 → 回课程复习或看错题本；
- **练习详情**：顶部若该题在错题本里，会说明「下次复习 YYYY-MM-DD · 当前间隔 N 天」。

## 5. 判题失败要能照着改

每条判题规则配一句中文要求（`requirement_labels`），失败时说：

> 第 3 项「用负一索引取报错的最后一行」没有出现

而不是「第 3 项必须出现的写法没有出现」。

注意页面上的**两套编号**：题面里的「1)、2)」是讲解顺序，判题只对照「判题检查项」那张表——两处文案都写明了这一点，否则学习者会数错表。

## 6. 刻意保留的粗糙（不要当 bug 修）

| 现象 | 为什么保留 |
| --- | --- |
| 计划理由很长，一天能占好几行 | 它是「为什么排这项」的唯一解释来源；缩短就失去了可解释性 |
| 首页、计划页、进度页都有「本页只读」类说明 | 这个产品的写操作集中在少数页面，其余页面明确只读，避免误以为能点 |
| 判题对语法错误直接判失败并报行号 | 语法都不合法的代码不可能跑通；说「通过」是骗人 |
| 自检通过不推进错题本 | 错题本的意义是重新考一次，声明不足以证明；勾三次就清空错题本会让整个复习系统失效 |
| 复习优先于新练习，复习密集的周可能没有新练习 | 重考错过的题比多做新题更有价值；这一点在计划页写明了 |

## 7. 已知缺口（能力边界，不是缺陷）

| 缺口 | 原因 |
| --- | --- |
| 没有鉴权、没有多用户 | 单用户本地 MVP 的设计取舍；也因此没有第三方评审，结业作品只能本人自评 |
| 不执行用户代码 | 判题是文本比对 + 语法解析；沙箱不在这个版本的能力范围内，也不会用普通容器冒充 |
| 静态规则可被高级作弊绕过 | 注释与 docstring 已剥离，但**字符串常量里的文本仍参与匹配**；彻底解决需要真正执行代码 |
| 分页只有 `limit` | 数据量小；`GET /diagnostics/history` 的 `cursor` 是唯一例外 |
| 复习项永不删除 | 复习历史本身是证据；完成即 `status='done'`，不物理删除 |
| 错题本没有「我记住了」按钮 | 推进靠**重做那道练习并通过判题**；`POST /review/items/{id}/result` 接受自报结果，界面刻意不接（见 [API.md §6.1](API.md)） |
| 有 4 个端点界面从不调用 | 各有理由（自报式复习、生成前预览、跨练习时间线、运维入库），见 [API.md §6.1](API.md) |

## 8. 走查方法（供后续维护者复用）

新增或改动交互后，建议按这个顺序自查一次：

1. **空库**：`CREATE DATABASE` + `alembic upgrade head`，把 API 指过去，从 `/` 走到 `/projects`；
2. **有数据**：切回开发库，重复同一条路径，确认空状态文案不会打扰老用户；
3. **失败路径**：故意提交错代码，看提示是否可操作；
4. **重建前端**：`npm run build` 后再看——**不重建会看到旧界面**，这一条坑过好几次（见 [CONTRIBUTING §7.1](../CONTRIBUTING.md)）。
