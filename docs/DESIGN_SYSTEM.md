# AI Learning Copilot 设计系统

**文档版本**：v1.0（Sprint 0 基线）
**适用范围**：apps/web 的全部界面
**上游文档**：PRD.md（功能与文案逻辑）、ARCHITECTURE.md（页面与请求层边界）、ROADMAP.md（哪些入口暂标开发中）

本文档是界面实现的唯一取值来源。颜色、字号、间距、圆角、动效时长一律从这里取，不允许在组件里临时发明数值。所有取值与 Sprint 0 权威决策表一致。

## 1. 视觉方向

### 1.1 定位

现代开发者工具风格：信息层级靠字号、字重、间距与留白建立，而不是靠颜色堆叠。参考 Linear 与 Vercel 的克制感：界面安静、密度适中、每个颜色都有语义、动效只用于交代因果关系。

具体表现：

- 浅色与深色两套主题共用同一套结构，只换颜色变量；主题为三态（浅色、深色、跟随系统），默认跟随系统，用户可手动切换。
- 1px 细边框定义区块，阴影只用一层柔和阴影，不叠加。
- 强调色只出现在主操作、当前导航项、可交互焦点与关键数据上，全屏强调色面积不超过 10%。
- 数据页优先保证数字可读：等宽数字、右对齐、单位分离。
- 中文正文按 15px 起排，行高不低于字号的 1.5 倍，避免密排造成阅读疲劳。

### 1.2 明确要避免的

| 避免项 | 原因 |
|---|---|
| 渐变背景、发光边框、玻璃拟态 | 干扰信息层级，且在深色下对比度不可控 |
| 机器人、AI 大脑、火箭等插画 | 与"学习工具"的克制定位冲突，且会过时 |
| 大圆角（16px 以上）与胶囊按钮 | 削弱开发者工具的锐利感，降低信息密度观感 |
| 多层阴影与悬浮卡片堆叠 | 边界不清，长列表滚动时视觉噪声大 |
| 装饰性动画与滚动视差 | 学习场景需要专注，动效只用于状态变化 |
| 营销式大标题与 Hero 区 | 首屏应直接给今日待办，不做宣传位 |
| 用颜色作为唯一状态指示 | 色觉障碍用户不可用，必须配图标或文字 |
| 完成率当掌握度展示 | 与产品原则冲突，见 PRD.md 第 3 节与模块 8 |

## 2. 颜色系统

### 2.1.1 语义色与「重点块」（v0.1.48 起）

早期界面只有一种靛蓝 + 大面积灰，讲义读起来是一堵灰墙。现在补了一套**语义色**，让四类信息在视觉上分得开：

| 令牌 | 用在哪 | 浅色 | 深色 |
|---|---|---|---|
| `--info` / `--info-soft` / `--info-line` | 自测问题、提示性说明 | #0369a1 / #f0f9ff / #bae6fd | #38bdf8 / #0b1a24 / #0e3a4f |
| `--success(-soft/-line)` | 通过项、运行输出、改法 | #16a34a / #f0fdf4 / #bbf7d0 | #16a34a / #071a10 / #14532d |
| `--warning(-soft/-line)` | 典型错误（坑）、注意 | #d97706 / #fffbeb / #fde68a | #d97706 / #1c1405 / #4a3208 |
| `--danger(-soft/-line)` | 未通过项、错误写法 | #dc2626 / #fef2f2 / #fecaca | #f87171 / #1c0a0a / #4c1d1d |
| `--accent-line` | 学习目标、判题要求清单 | #c7d2fe | #3730a3 |
| `--code-bg` / `--code-fg` / `--code-muted` | 代码块（两种主题都用深色底） | #0f172a / #e2e8f0 / #94a3b8 | #0b1220 / 同 / 同 |

**一条约定**：颜色只用来区分**信息的种类**，不用来装饰；同一页面里同一种颜色只代表同一种含义。

对应组件 `src/components/callout.tsx`：

| 组件 | 用途 |
|---|---|
| `<Callout tone title>` | 左侧色边 + 淡色底的重点块；`tone` 取 accent / info / success / warning / danger |
| `<InlineCode>` | 行内代码：`nums[0]`、`d.get("score", 0)` 这类片段从中文里跳出来 |
| `<RichText text>` | 讲义正文；**自动**把「标识符 + 方括号/圆括号」识别为行内代码，也支持反引号 |

讲义各节现在长这样：学习目标 = accent 块；讲解 = 带编号与色条的分节；代码示例 = 深色终端块 + 绿色「运行输出」块；典型错误 = warning 块（红底错误写法 + 琥珀「为什么错」+ 绿「怎么改」）；自测 = info 块。
### 2.1 基础令牌

浅色与深色各一套，变量名相同。所有值为小写十六进制。

| 令牌 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| canvas | 页面背景 | #ffffff | #0a0a0a |
| surface | 卡片、次级区块背景 | #fafafa | #111111 |
| border | 1px 边框、分隔线 | #e5e5e5 | #262626 |
| text | 主文字 | #0a0a0a | #ededed |
| text-muted | 次级文字、说明 | #6b6b6b | #a1a1a1 |
| accent | 强调色：主操作、当前项、焦点 | #4f46e5 | #818cf8 |
| success | 成功、通过 | #16a34a | #16a34a |
| warning | 警告、待处理 | #d97706 | #d97706 |
| danger | 错误、失败 | #dc2626 | #dc2626 |

### 2.2 语义色在文本场景的可用性

语义色作为填充或图标时可直接用基础令牌；作为文本时必须满足 4.5:1。实测对比度如下（背景分别为 #ffffff 与 #0a0a0a）：

| 语义色 | 浅色下作文本 | 深色下作文本 | 结论 |
|---|---|---|---|
| accent #4f46e5 / #818cf8 | 6.18:1 | 6.32:1 | 两套均可作文本 |
| success #16a34a | 3.30:1 | 6.00:1 | 浅色不可作小字文本 |
| warning #d97706 | 3.19:1 | 6.21:1 | 浅色不可作小字文本 |
| danger #dc2626 | 4.83:1 | 4.10:1 | 浅色可，深色不可作小字文本 |

因此新增三个派生文本令牌，只在这些场景替换，不改变上面的基础令牌取值：

| 派生令牌 | 取值 | 用在 | 对比度 |
|---|---|---|---|
| success-text | #15803d（浅色） | 浅色下"已通过"等文本 | 5.02:1 |
| warning-text | #b45309（浅色） | 浅色下"待复习"等文本 | 5.05:1 |
| danger-text | #dc2626（浅色）/ #f87171（深色） | 两套主题下的错误文本 | 4.83:1 / 7.16:1 |

规则：填充块与图标用基础令牌，文本用派生令牌；同一处不得混用两套取值。

### 2.3 已知可访问性权衡

border #e5e5e5 与 canvas #ffffff 的对比度约 1.26:1，低于 WCAG 1.4.11 对 UI 组件边界要求的 3:1。这是本设计系统已知的取舍，补偿措施固定为三条，不得省略：

1. 输入控件使用 surface #fafafa 填充加 1px 边框，边界同时由填充对比产生。
2. 聚焦时显示 2px accent 焦点环，偏移 2px，保证键盘用户可定位。
3. 所有控件必须有可见 label，不用 placeholder 代替 label。

长期方案（提高 border 令牌对比度）记入第 10 节待确认，不在本次擅自改动令牌。

### 2.4 使用约束

- 单个视图内强调色元素不超过 3 处。
- 语义色不用于装饰（例如不用 success 绿色画图标底板）。
- 不用纯黑 #000000 与纯白 #ffffff 之外的近似值替代 canvas 与 text。
- 图表配色只用 accent、text-muted 与 border 三者的不同透明度，不引入彩虹色板。

## 3. 字体与排版

### 3.1 字体栈

| 用途 | 字体 |
|---|---|
| 界面文本 | Geist Sans，回退 PingFang SC、Microsoft YaHei、系统无衬线 |
| 代码与等宽数字 | Geist Mono，回退 ui-monospace、Menlo、Consolas |

- 由 next/font 加载 Geist 与 Geist Mono，变量名沿用 --font-geist-sans 与 --font-geist-mono。
- 中文回退必须显式声明 PingFang SC 与 Microsoft YaHei，不允许只写 sans-serif。
- 代码块、路径、接口名、表名、字段名一律等宽字体。
- 数字使用等宽数字（font-variant-numeric: tabular-nums），保证列对齐。

### 3.2 字号与行高梯度

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| 页面标题 | 28px / 36px | 600 | 每页唯一的 h1 |
| 区块标题 | 22px / 30px | 600 | 页面内主要分区 |
| 卡片标题 | 18px / 26px | 600 | 卡片与小节 |
| 正文 | 15px / 24px | 400 | 课程正文、说明段落 |
| 次要正文 | 14px / 22px | 400 | 表单标签、列表元信息 |
| 说明文字 | 13px / 20px | 400 | 时间、来源、提示 |
| 数据强调 | 24px / 32px | 600 | 掌握度、通过率等关键数字 |
| 代码 | 13px / 20px | 400 | 代码块、字段名 |
| 徽标文字 | 12px / 16px | 500 | 状态徽标 |

规则：

- 全站字号只取上表九个值，不新增第 10 级。
- 中文正文行高不低于字号的 1.5 倍；西文混排同样适用，不压缩行高换密度。
- 标题不使用全大写与拉宽字距；中文不使用 letter-spacing。
- 一段文字内最多两种字重；强调优先用字重，其次才用颜色。
- 长文本宽度上限 72 个半角字符（约 36 个汉字），课程正文放宽到 80 个半角字符。

## 4. 间距与栅格

### 4.1 间距刻度

基于 4px 栅格，只使用下列值：4、8、12、16、20、24、32、40、48、64。

| 场景 | 取值 |
|---|---|
| 图标与文字之间 | 8px |
| 徽标与标题之间 | 8px |
| 表单标签与输入框 | 8px |
| 表单字段之间 | 16px |
| 卡片内边距 | 20px（紧凑）/ 24px（常规） |
| 卡片之间 | 16px |
| 区块之间 | 32px |
| 页面上下留白 | 32px（桌面）/ 24px（平板）/ 16px（移动） |
| 列表行内边距 | 12px 16px |

### 4.2 栅格

- 内容区 12 列，列间距 24px（桌面）、16px（平板）。
- 卡片排布优先使用 CSS Grid：桌面 2 列或 3 列，平板 2 列，移动 1 列。
- 不做像素级绝对定位布局；除侧边导航与顶栏外不用 fixed 定位。

## 5. 布局规范

### 5.1 整体结构

```text
+----------------+---------------------------------------------+
| 侧边导航 240px | 顶栏 56px（sticky，1px 下边框）              |
|                +---------------------------------------------+
| 今日 /         |                                             |
| 学习 /learn    | 内容区 max-width 1200px，水平居中            |
| 练习 /practice | padding 32px                                |
| 项目 /projects |                                             |
| 进度 /progress |                                             |
+----------------+---------------------------------------------+
```

- 侧边导航固定宽 240px，整屏高度，右侧 1px border 分隔，背景 canvas，不投影。
- 顶栏高 56px，sticky，背景 canvas 加 1px 下边框；左侧放当前页面标题，右侧放环境状态徽标（数据服务、AI 服务）。
- 内容区最大宽 1200px，水平居中；超过 1200px 的屏幕靠留白扩展，不拉宽内容。
- 内容区不与侧边导航重叠；滚动只发生在内容区。

### 5.2 响应式断点与形态

| 断点 | 宽度 | 侧边导航形态 | 内容区 |
|---|---|---|---|
| 桌面 | ≥ 1024px | 240px 常驻 | max-width 1200px，padding 32px |
| 平板 | 768–1023px | 收为图标栏 64px，可展开为浮层 | padding 24px，2 列 |
| 移动 | < 768px | 隐藏，顶栏左侧汉堡按钮打开抽屉 | padding 16px，1 列 |

移动端导航形态固定为抽屉（从左滑出，宽 280px，带遮罩），不使用底部标签栏：标签栏会与"今日待办"的主操作抢空间，且五个页面里项目与进度的使用频率低，不适合常驻。

抽屉行为：Esc 关闭、点击遮罩关闭、焦点移入抽屉并循环、关闭后焦点回到汉堡按钮。

### 5.3 页面级布局约定

| 页面 | 主结构 |
|---|---|
| /（今日） | 三张区块卡：复习、学习、练习，垂直排列，每块含标题、数量、操作按钮 |
| /learn | 左侧课程目录（宽 280px）+ 右侧正文，移动端合并为单列并折叠目录 |
| /practice | 上方题目区，下方代码区与运行输出粘贴区，右侧或下方判定结果卡 |
| /projects | 卡片列表 + 详情抽屉，清单项用复选列表 |
| /progress | 2×2 区块网格（桌面）/ 单列（移动），每块含标题、区间说明、数据与来源 |

## 6. 组件规范

每个组件给出何时用、何时不用与规格。所有组件放在 apps/web/src/components，不允许在页面里重复实现同一组件。

### 6.1 按钮

**何时用**：触发一次明确动作（提交、开始诊断、重试、标记掌握度）。
**何时不用**：导航跳转（用链接）、状态展示（用徽标）、切换视图（用分段控件）。

| 变体 | 外观 | 用途 |
|---|---|---|
| primary | accent 背景 + 白色文字 | 页面唯一主操作 |
| secondary | surface 背景 + 1px border | 次级操作 |
| ghost | 无背景无边框，hover 时 surface | 行内操作、图标按钮 |
| danger | danger 背景 + 白色文字 | 删除、清空 |

规格：高度 32 / 36 / 40px 三档，圆角 6px，水平内边距 12 / 16px，字号 14px 500；同一视图内 primary 最多 1 个；图标按钮必须有 aria-label；按下态用 0.98 缩放，不做位移动画。

### 6.2 卡片

**何时用**：承载一组同类信息，需要与背景区分（今日待办三块、进度四块）。
**何时不用**：整页只有一块内容、或信息本身是表格/列表（用表格与列表，不套卡片）。

规格：背景 surface，1px border，圆角 8px，内边距 20 或 24px，单层柔和阴影（0 1px 2px rgba(0,0,0,0.04)）；卡片内不嵌套卡片；卡片标题使用 18px/600；右上角可放状态徽标。

### 6.3 导航项

**何时用**：侧边导航与抽屉中的五个页面入口。
**何时不用**：页面内的分段切换（用分段控件）、面包屑。

规格：高 40px，圆角 6px，左内边距 12px，图标 16px 与文字间距 8px；默认 text-muted，hover 时 text 加 surface 背景，当前项用 accent 文字 + surface 背景 + 左侧 2px accent 竖条；当前项必须有 aria-current="page"；未开发页面的导航项保留但标注开发中（见 7.3）。

### 6.4 状态徽标

**何时用**：表达离散状态（已通过、待复习、开发中、AI 未配置）。
**何时不用**：表达数量（用文本）、表达进度（用进度条）、表达长句（用提示条）。

规格：高 20px，水平内边距 8px，圆角 999px（徽标是唯一允许胶囊形状的组件），字号 12px 500；五类变体：neutral（border + text-muted）、accent（accent 文字 + 10% accent 背景）、success、warning、danger（各自 10% 背景 + 对应文本令牌）；必须同时有文字，不能只有颜色；"开发中"用 neutral 加虚线边框。

### 6.5 表格

**何时用**：多行多列的对比数据（提交历史、错题列表）。
**何时不用**：少于 3 行（用列表）、需要卡片化展示的富内容。

规格：表头 13px 500 text-muted，行高 44px，行内边距 12px 16px；数字列右对齐并使用等宽数字；不使用斑马纹，hover 行用 surface；1px 横向分隔线，不画纵向网格线；移动端（<768px）转为卡片列表，不横向滚动；表格必须有 caption 或可见标题。

### 6.6 表单

**何时用**：诊断答题、练习提交、项目地址填写、每周时长设置。
**何时不用**：只有 1 个开关的简单设置（用开关组件）、纯筛选（用筛选条）。

规格：label 在输入上方，14px 500，必填项在 label 后加"必填"文字而非星号；输入框高 36px（单行）、圆角 6px、1px border、聚焦时 2px accent 环；错误文案在输入下方 13px danger-text，并通过 aria-describedby 关联；校验时机为失焦与提交，不在每次按键时报错；不得用 placeholder 代替 label。

### 6.7 空状态

**何时用**：确实没有数据（今日无到期复习、还没有提交记录）。
**何时不用**：加载中（用骨架）、加载失败（用错误态）、权限不足。

规格：垂直居中，包含一句说明（不超过 20 字）、一句补充（说明何时会有数据）、最多一个次操作按钮；不使用插画，可用 1px 线条图标；空状态不得掩盖错误：请求失败必须显示错误态而不是空状态。

### 6.8 加载骨架

**何时用**：请求超过 300ms 才显示，用于页面首屏与区块替换。
**何时不用**：短于 300ms 的请求（直接显示结果）、按钮提交（用按钮内 loading）。

规格：骨架形状必须与真实内容结构一致（行数、块高、圆角）；颜色用 border 到 surface 的过渡；循环动画 1.2s，prefers-reduced-motion 时改为静止；同屏最多 3 个骨架区块；数据到达后整体替换，不做逐块闪烁。

### 6.9 错误态

**何时用**：请求失败、数据服务不可用、AI 服务未配置。
**何时不用**：表单字段校验（用内联错误文案）、空数据。

规格：包含三件事：发生了什么（中文，一句话）、可以做什么（重试按钮或返回今日页）、request_id（可复制，13px 等宽）；重试按钮为 secondary；不显示堆栈；不显示英文错误原文；错误态占位与骨架同高，避免布局跳动。

### 6.10 主题切换控件

**何时用**：顶栏右侧，用户需要改变界面主题时（浅色、深色、跟随系统三态）。
**何时不用**：页面内容区、卡片内、表单内。主题是全局设置，不随局部场景出现。

规格：桌面为三态分段控件，宽度不足以并排时降级为下拉；三态都必须有可读文字标签"浅色""深色""跟随系统"，不允许只显示图标；当前态用 accent 文字加 surface 背景，并带 aria-checked 或 aria-selected；高度 32px，圆角 6px，与按钮规格一致。
键盘要求：整组只有一个 Tab 停靠点（roving tabindex），左右方向键在选项间移动，Home 与 End 跳到首尾，Enter 或空格确认；聚焦时显示 2px accent 焦点环与 2px 偏移。切换后立即生效，不整页刷新，并在 aria-live="polite" 区域播报"已切换为深色"这类结果。

## 7. 交互原则

### 7.1 反馈时延分级

| 时延 | 反馈形态 |
|---|---|
| ≤ 100ms | 立即态：按钮按下、选中高亮、开关切换，不显示加载 |
| 100–300ms | 保持当前内容，可通过禁用态表达处理中 |
| 300ms–1s | 骨架屏替换目标区域 |
| 1–10s | 骨架 + 文案（如"正在判题"），提供取消（若可取消） |
| > 10s 或超时 | 错误态，说明超时并给出重试；AI 对话超时为 60s，超时前可手动停止 |

### 7.2 禁用态

- 禁用必须有原因，且原因对用户可见：按钮禁用时在按钮下方或 tooltip 说明（例如"请先粘贴运行输出"）。
- 禁用态仍要可读：文字对比度不得低于 4.5:1，只用背景与边框弱化。
- 使用 aria-disabled 而不是仅 opacity，保留可聚焦以便屏幕阅读器解释原因。
- 提交类操作在请求进行中禁用，防止重复提交；禁止用禁用代替后端校验。

### 7.3 开发中功能的标注规范

任何尚未可用的入口，必须同时满足四条，缺一条视为缺陷：

1. 显示状态徽标"开发中"（neutral 变体加虚线边框）。
2. 交互禁用：点击不发起网络请求、不跳转、不出现空白页；用 aria-disabled 表达。
3. 附一句说明：预计在哪个 Sprint 提供（写 Sprint 编号，不写日期承诺）。
4. 不隐藏入口：导航项保留可见，避免用户以为功能被删除。

合规文案："开发中 · 预计 S4 提供"。禁止使用任何同义替代说法（含中文口语化表达与英文表述），"开发中"是本产品唯一用语。

### 7.4 可访问性

- 对比度：正文 ≥ 4.5:1，大字号（≥ 18.66px 粗体或 24px 常规）≥ 3:1，UI 边界 ≥ 3:1（已知例外见 2.3）。
- 焦点：2px accent 焦点环 + 2px 偏移，任何可交互元素都必须有可见焦点，禁止 outline: none。
- 键盘：Tab 顺序与视觉顺序一致；Esc 关闭抽屉、对话框与浮层；对话框内焦点循环，关闭后焦点归还触发元素。
- 语义：每页 1 个 h1；主区域用 main，导航用 nav，并带可见或隐藏标题；表单控件必须有关联 label。
- 动态状态：异步结果用 aria-live="polite" 播报（如"判题完成，通过"），不用 aria-live 播报连续流式文本。
- 触控目标：不小于 44×44px（可含透明内边距）。
- 减少动效：prefers-reduced-motion: reduce 时禁用位移、缩放与循环动画，仅保留透明度变化。

### 7.5 动效

- 只用于交代状态变化：出现、消失、替换、焦点移动。
- 时长 120–200ms，硬上限 300ms；超过 300ms 的入场动画一律不允许。
- 缓动统一 ease-out；不使用弹跳与回弹曲线。
- 同一时刻最多一个元素动效；列表不做逐项延迟入场。

## 8. 反模式清单

出现以下任一项，评审直接不通过：

1. 使用渐变、发光、玻璃拟态或彩色阴影。
2. 使用机器人、AI 大脑、火箭、灯泡等插画。
3. 圆角超过 8px（徽标除外），或按钮做成胶囊形。
4. 同一视图出现 2 个以上 primary 按钮。
5. 用颜色作为唯一状态指示，没有文字或图标配合。
6. 用 opacity 表达禁用而不给原因。
7. 用 placeholder 代替 label，或用星号代替"必填"文字。
8. 请求失败时显示空状态或 0 值，掩盖错误。
9. 用完成率文案表达掌握度（例如"已完成 80%，掌握良好"）。
10. 加载骨架形状与真实内容不一致，导致布局跳动。
11. 动效超过 300ms，或使用滚动视差、自动轮播。
12. 未完成功能不标注、点击跳 404 或空白页。
13. UI 文案用同义替代说法替代"开发中"（唯一正确用语见 7.3）。
14. 在组件里写死颜色、字号、圆角或间距，而不是引用令牌。
15. 图表使用默认彩虹色板或渐变填充。
16. 使用全大写英文标题或给中文加字距。

## 9. 实现映射

### 9.1 令牌落地位置

- 颜色变量定义在 apps/web/src/app/globals.css 的 :root 中；深色同名变量由 html 元素上的 dark class 覆盖（选择器见 9.2，策略见 9.4），不使用媒体查询分支，避免与用户的手动选择冲突。
- 用 Tailwind CSS 4 的 @theme inline 把变量映射为工具类变量名（颜色、圆角、字体、容器宽度、导航宽度），页面只使用映射后的类名。
- 映射时有两处改名，避免与 Tailwind 内置工具类同名冲突：border 颜色映射为 line（类名 border-line），主文字映射为 ink（类名 text-ink）。其余令牌与第 2.1 节同名。
- 字体在 apps/web/src/app/layout.tsx 用 next/font 加载，变量名 --font-geist-sans 与 --font-geist-mono。
- 组件在 apps/web/src/components；页面只在 apps/web/src/app 下组装。

### 9.4 主题策略

主题为三态：浅色、深色、跟随系统。默认值为跟随系统；用户的选择持久化到 localStorage（键名以实现为准，本文档不锁定具体键名），选择优先于系统偏好。

无闪烁实现：在 layout 的 head 内联一段同步脚本，在首屏绘制前读取持久化的主题选择；选择为深色，或选择为跟随系统且系统偏好为深色时，立即给 html 元素加 dark class，否则不加。该脚本必须位于任何样式表与正文之前，禁止放进 useEffect 或异步加载的模块，否则会出现首帧闪白或闪黑。

绘制与切换约定：服务端渲染不依赖主题（按默认值输出），由内联脚本在绘制前修正；切换主题不整页刷新，只切换 html 元素的 dark class，颜色变量随之生效；系统偏好变化时，仅在用户选择为"跟随系统"的情况下跟随切换。深色令牌选择器为 .dark，不使用 prefers-color-scheme 分支，避免用户显式选择浅色时被系统偏好覆盖。主题切换控件与键盘要求见 6.10，切换结果的播报见 7.4。

## 10. 待确认事项

- 待确认：border 令牌对比度（1.26:1）是否需要提升到 3:1。当前以 2.3 节的三条补偿措施过渡；若提高，涉及全局视觉变化，需产品与前端共同确认。
- 待确认：语义色的派生文本令牌（success-text、warning-text、danger-text）是否被接受为正式令牌。若不接受，退路是语义色只用于非文本元素，文本一律用 text 与 text-muted。
- 待确认：首版是否引入图表库。当前约束是首页 JS 不超过 250KB gzip，优先用内联 SVG 实现掌握度分布与通过率趋势。
- 待确认：移动端导航是否最终采用抽屉。当前结论是抽屉而不是底部标签栏，若真实使用中移动端占比上升，再重新评估。
